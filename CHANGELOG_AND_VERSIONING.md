# Changelog and Versioning

Release tags follow SemVer-style `vMAJOR.MINOR.PATCH`. Tags are immutable. Do not delete/recreate a published tag to repair a release; create a new patch/prerelease instead.

GitHub Releases generate notes from merged changes, but important breaking API/event/migration changes should also be called out manually. The release manifest is the machine-readable source of deployed image digests; release notes are human-readable context.
